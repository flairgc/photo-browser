# Photo Browser

## Источник фотографий

Все настройки находятся в **корневом `.env`**. Шаблон — `.env.example`.
После изменения настроек перезапустите сервер. Переменные окружения команды
имеют приоритет над `.env`. Пароль NAS не выводится в конфигурационный лог.

Локальная папка:

```dotenv
BACKEND_DATA_SOURCE=local
BACKEND_FS_ROOT=/storage/emulated/0/Pictures
BACKEND_FS_ROOT_DEV=
```

`BACKEND_FS_ROOT_DEV` переопределяет папку в режиме разработки, если заполнена.
Для прежних конфигураций относительные пути фотографий считаются от `backend/`.
Лучше указывать абсолютные пути.

NAS по SMB (без mount и root-доступа):

```dotenv
BACKEND_DATA_SOURCE=nas
BACKEND_NAS_HOST=192.168.1.10
BACKEND_NAS_PORT=445
BACKEND_NAS_SHARE=photos
BACKEND_NAS_PATH=Family/2026
BACKEND_NAS_USERNAME=photo-user
BACKEND_NAS_PASSWORD='your-password'
BACKEND_NAS_DOMAIN=
BACKEND_CACHE_DIR=/storage/emulated/0/PhotoBrowserCache
BACKEND_CACHE_WARMUP=false
```

Это соответствует `\\192.168.1.10\photos\Family\2026`. `SHARE` — имя сетевой
общей папки, `PATH` — подпапка внутри неё; пустой `PATH` открывает всю общую папку.
`HOST` задаётся без `smb://`. Домен оставьте пустым, если NAS его не требует.
Пароли с `#` или пробелами заключайте в кавычки. Настройки NAS общие для dev и production.
Локальные пути фотографий в режиме NAS не нужны.

Используется [@awo00/smb2](https://github.com/awo00/smb2), клиент SMB2 на Node.js.
Папки, оригиналы, EXIF, миниатюры и ZIP работают через выбранный источник.
Телефон должен иметь сетевой доступ к NAS и порту SMB; учётной записи нужны права
чтения выбранной папки. Совместимость с настройками SMB конкретного NAS следует
проверить на устройстве. На NAS в локальной сети проверены список папок, оригинал,
EXIF, ZIP, создание маленького превью и повторная выдача из кеша через API.

## Кеш миниатюр

- `BACKEND_CACHE_WARMUP=false` (по умолчанию): сервер не сканирует коллекцию при
  запуске. Превью создаются при запросе из браузера и сохраняются для повторного использования.
- `BACKEND_CACHE_WARMUP=true`: после запуска сервера начинается фоновый обход
  всей выбранной папки с подпапками, последовательно создаются маленькие превью.
- `BACKEND_CACHE_DIR=`: прежнее расположение `.cache_photo_browser_app` внутри
  папки фотографий. В режиме NAS это папка **на NAS**, нужны права записи в неё.
- Непустой `BACKEND_CACHE_DIR` всегда означает локальный путь на машине с Node.js.
  Например, `/storage/emulated/0/PhotoBrowserCache` сохраняет превью на телефоне,
  даже если оригиналы находятся на NAS. Относительные пути кеша считаются от корня проекта.

Кеш исключён из списка папок и полного обхода. Существующие локальные ключи кеша
сохранены. Повторный прогрев использует готовые превью. Как и раньше, при замене
оригинала по тому же пути для обновления превью потребуется очистить соответствующий кеш.
Большие превью (2560 px) создаются при открытии фотографии; маленькие — 200 px.
При подготовке одного превью с NAS оригинал загружается в память телефона.
Оригиналы и ZIP передаются потоками. Временный ZIP на NAS не создаётся.

Команды **из корня проекта**:

| Команда | Действие |
| --- | --- |
| `npm start` | Обычный запуск с настройками `.env` |
| `npm run start:warmup` | Запуск приложения и фоновое создание всех маленьких превью |
| `npm run cache:warmup` | Создание всех маленьких превью без сервера, затем выход |
| `npm run cache:warmup -- --all-sizes` | Создание маленьких и больших превью без сервера |
| `npm run dev` | Режим разработки |
| `npm run dev:warmup` | Режим разработки с фоновым прогревом |
| `npm --workspace backend run cache:warmup:dev` | Прогрев папки разработки без сервера |
| `npm run test:backend` | Проверки backend |

Отдельная команда прогрева использует production-папку `BACKEND_FS_ROOT` и
завершается с ненулевым кодом, если часть миниатюр создать не удалось.
Кнопка остановки / Ctrl+C прерывает сервер. Прогрев большой коллекции может занять время.

## Android / Termux

Проект и node_modules держите в домашней папке Termux: ~/projects/photo-browser.
Для первого запуска выполните:

```sh
pkg update
pkg install nodejs-lts python make clang pkg-config libvips
cd ~/projects/photo-browser
npm run setup:termux
npm run dev
```

Откройте http://localhost:5173 в браузере телефона. Для обычного запуска используйте
`npm start` и http://localhost:4173. Нужен Node.js 22.12+ или 24+.

### Почему обычного npm install может не хватить

Для Android ARM64 sharp 0.33 не поставляет готовый нативный модуль. Его нужно собрать
с системным libvips (минимум 8.15.3). Без сборки backend завершится с ошибкой
`Could not load the "sharp" module using the android-arm64 runtime`, хотя Vite запустится.
См. [инструкцию sharp](https://sharp.pixelplumbing.com/install/).

В проект добавлены инструменты node-gyp и node-addon-api. Команда
`npm run setup:termux` проверяет системные зависимости, устанавливает npm-пакеты,
включает C++17 для сборки и использует заголовки Node.js из Termux. C++17 необходим
для node-addon-api 8; стандартные настройки sharp 0.33 используют C++11.
В конце команда проверяет реальное создание JPEG. Если прежняя установка sharp
была неполной, команда также запускает его пересборку.

После неудачного npm install, переустановки зависимостей или обновления Node.js
повторите `npm run setup:termux`. Не переносите node_modules с Windows на телефон.
На Windows и обычном Linux продолжайте использовать `npm install`.

Проверено на телефоне через SSH: Android ARM64, Node.js 24.18.0, libvips 8.18.6.
Проходят установка, backend-тесты и сборки обеих частей. В режиме разработки
проверены пять миниатюр с NAS, большое превью, EXIF и скачивание оригинала;
кеш сохранялся локально в домашней папке Termux.
Также исправлена обработка промежуточного ответа SMB STATUS_PENDING: приложение
дожидается окончательных данных NAS, что предотвращает повреждение читаемых фотографий.

### Кеш на телефоне и доступ к NAS

Для кеша в общей памяти телефона выполните `termux-setup-storage` и выдайте разрешение.
В корневом .env задайте:

```dotenv
BACKEND_CACHE_DIR=/storage/emulated/0/PhotoBrowserCache
BACKEND_CACHE_WARMUP=false
```

Альтернатива без доступа к общей памяти:
`BACKEND_CACHE_DIR=/data/data/com.termux/files/home/.cache/photo-browser`.
Папка создаётся автоматически. После изменения .env перезапустите сервер.

В .env оставьте `VITE_BACKEND_API_HOST=http://localhost`: backend работает на телефоне,
а адрес NAS используется только сервером для SMB.
